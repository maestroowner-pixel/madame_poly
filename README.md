# Madame Poly

Личное приложение для голосовой практики разговорной речи на английском, немецком,
французском и испанском. Говоришь → Whisper распознаёт → Claude отвечает и разбирает
ошибки → ответ озвучивается.

Исходная спека: [`docs/Polyglotta.pdf`](docs/Polyglotta.pdf).

## Запуск

```bash
cp .env.example .env      # подставить конфиг Firebase (ключи API живут на сервере)
npm install
npm run go                # Expo Go
```

Нативные проекты сгенерированы и лежат в `ios/` и `android/` (в git не
попадают — их всегда можно пересобрать):

```bash
npx expo prebuild --platform all --clean   # пересобрать оба
npm run android                            # сборка и запуск Android
npm run ios                                # сборка и запуск iOS
```

`npm run ios` в этом окружении не соберётся — см. раздел об ограничениях.

Микрофон недоступен в Expo Go на web — запускать на устройстве или симуляторе
(`i` / `a` в терминале Expo).

### Проверка прокси без UI

```bash
npm run smoke            # английский, B1
npm run smoke -- de A2   # немецкий, A2
```

Скрипт входит в Firebase анонимно, озвучивает фразу с намеренными ошибками,
распознаёт её обратно через Whisper и просит Claude найти ошибки — всё через
прокси-функцию `api`, как это делает приложение. За один прогон проверяются
вход, ключи на сервере и все три маршрута, не трогая симулятор.

Кто ведёт реплику, переключает кнопка «АВТО» слева от главной полосы.
Подсвечена — приложение ловит паузу само и сразу слушает дальше.

Погашена — реплику ведёте вы целиком: после ответа собеседницы микрофон не
открывается, полоса показывает «Ответить» и ждёт нажатия. Так и задумано:
человеку нужно время прочитать ответ и придумать свой, а не отвечать сразу после
гудка. Нажали — пошла запись, полоса стала «Готово»; беседа закрывается долгим
нажатием. Ручной
режим нужен тем, кто говорит медленно: авто режет фразу на первой же паузе.

Отдельной строки под выбор режима нет намеренно — на маленьком экране высота
дороже. Во время беседы кнопка заблокирована: смена режима на полуслове сбила бы
запись. Потолок реплики `MAX_TURN_MS` работает в обоих режимах.

Осциллограмма входа рисуется фоном внутри главной полосы: видно, открыт ли
микрофон, и это не занимает отдельной панели. Портрет собеседницы стоит по центру шапки, значок языка — слева, действия
справа. Боковые группы одной ширины, иначе портрет уехал бы вправо: слева одна
кнопка, справа две.

Дальше — про авторежим. Беседа идёт без тапов, как в Loora: нажал «Начать беседу» — приложение слушает,
по паузе в речи само заканчивает реплику, отвечает голосом и снова слушает.
Границу реплики определяет по уровню входного сигнала (`isMeteringEnabled` у
рекордера), пороги вынесены в `src/config.ts`:

Порог речи не абсолютный, а отсчитывается от шума комнаты и обновляется всю
беседу: фон меряется по паузам между словами. Разовая калибровка в начале не
годилась — тихая музыка или улица могут появиться на середине разговора.

Фон падает мгновенно и поднимается плавно (`NOISE_RISE`), а во время речи ползёт
вверх на порядок медленнее (`NOISE_RISE_SPEECH`). Второе — страховка: если шум
появился громче текущего порога, он будет принят за речь, и без медленного
подъёма оценка фона застыла бы навсегда. С ним приложение выбирается само,
примерно за пятнадцать секунд.

Замеренный фон зажат между `NOISE_FLOOR_MIN_DB` и `NOISE_FLOOR_MAX_DB`, чтобы
оценка не уехала в потолок и приложение не оглохло.

| Константа | По умолчанию | Что делает |
|---|---|---|
| `SPEECH_LEVEL_DB` | `-35` | нижняя граница порога: ниже он не опускается |
| `NOISE_MARGIN_DB` | `12` | насколько порог выше шума комнаты |
| `NOISE_RISE` | `0.05` | как быстро фон растёт на паузах |
| `NOISE_RISE_SPEECH` | `0.002` | то же во время речи — страховка от шума |
| `NOISE_FLOOR_MIN_DB` / `MAX` | `-60` / `-40` | границы доверия к замеру |
| `SILENCE_HOLD_MS` | `1300` | сколько тишины после речи завершает реплику |
| `MIN_SPEECH_MS` | `400` | минимум речи, чтобы не реагировать на шум |
| `MAX_TURN_MS` | `30000` | жёсткий потолок одной реплики |
| `METERING_INTERVAL_MS` | `100` | как часто опрашивать уровень |

Если пауза всё равно не ловится, поднимайте `NOISE_MARGIN_DB`; если реплику
обрывает на середине — снижайте его или увеличивайте `SILENCE_HOLD_MS`.

Если реплика оказалась шумом, а не речью, она не уходит в Whisper — приложение
молча слушает дальше. Под панелью языка стоит полоса с лицом собеседника слева
и осциллограммой входа справа: пока микрофон открыт, полоски дышат по громкости
и подпись говорит «Слушает»; как только приложение распознаёт, думает или
отвечает, линия выпрямляется. Без неё в режиме свободных рук непонятно, слышно
тебя сейчас или нет.

Беседа заканчивается сама, когда человек прощается: модель возвращает признак
`farewell` вместе с ответом, приложение даёт прощальной реплике доиграть и
закрывает сессию, а не уходит слушать снова. В промпте отдельно оговорено, что
пауза, короткий ответ или смена темы прощанием не считаются.

Тап по портрету увеличивает его, осциллограмма при этом становится короче.
Число полосок не задано числом, а считается по фактической ширине панели —
поэтому оно само подстраивается и под раскрытый портрет, и под планшет.

### Темы разговора

Если своей темы нет, в панели выбирается готовая — по тридцать четыре на язык в
`src/topics.ts`, с названием на изучаемом языке и переводом для быстрого выбора.
Двадцать девять тем общие, тридцатая своя у каждого языка: британский против
американского, Октоберфест, сыр и вино, фламенко.

Ещё четыре — ролевые ситуации: в банке, в аптеке, у врача с простудой и звонок
в сервис по ремонту бытовой техники. У них другой режим: партнёр играет
сотрудника, а не расспрашивает о впечатлениях, и описание сцены лежит в
`ROLEPLAY_SCENES` — по одному на ситуацию, а не на язык, потому что роль одна и
та же. В промпте для них своя ветка, и первая реплика тоже звучит в роли.

Готовых первых фраз в списке нет намеренно: одна и та же заготовка звучала бы
одинаково и на A1, и на C1. Тема уходит в system prompt, а открывающую реплику
партнёр придумывает сам под уровень и сразу её озвучивает. Выбор темы хранится
отдельно по каждому языку, «Свободная» возвращает обычный разговор.

Язык и уровень собраны в одну панель квадратных кнопок под шапкой. Она прячется
сама через `PANEL_AUTOHIDE_MS` (5 с) бездействия и сразу при старте беседы —
дальше она только отнимает место у ленты. В свёрнутом виде остаётся значок: флаг языка с уровнем поверх него. Строкой
это занимало половину шапки, значком — одну кнопку. По тапу панель
разворачивается обратно.

Язык и уровень — параметры, а не отдельные экраны: один system prompt обслуживает
все восемь языков, уровень хранится отдельно по каждому и регулирует сложность речи ИИ.

Ответ Claude приходит структурированным (`{ reply, corrections[] }`) через
structured outputs, поэтому реплика и разбор ошибок не смешиваются: `reply` уходит
в озвучку, `corrections` показываются под сообщением пользователя.

Каждое исправление состоит из четырёх частей: `original` и `corrected` —
что было и как правильно, `explanation` — одна строка на виду, `rule` и
`details` — название правила и разбор на две-четыре фразы с ещё одним примером.
Последние два прячутся за «?» рядом с пузырём: во время беседы грамматика
отвлекает, а после — это единственное, ради чего стоит вернуться к ленте.

## Решения по открытым вопросам из спеки

| Вопрос | Решение |
|---|---|
| OpenAI TTS или ElevenLabs | OpenAI `tts-1` — тот же ключ, что у Whisper. ElevenLabs вырезан: его бесплатные 10k символов кончаются на третьей сессии, а дальше он выходит в 30–60 раз дороже (см. «Голос собеседницы»). |
| System prompt партнёра | `src/prompts.ts`: роль, правила для устной речи, отдельные правила для разбора ошибок, поведение по каждому уровню CEFR. |
| Streaming в первой версии | Нет. Реплики короткие (1–3 предложения), а озвучка всё равно ждёт полного текста — выигрыш был бы небольшим. |
| Где хранить историю | Локально, AsyncStorage. Firebase не нужен: приложение личное и одноустройственное. |

## Отличия от спеки

- **`expo-audio` вместо `expo-av`.** `expo-av` удалён в SDK 55+; проект на SDK 57.
- **Ключи API — на сервере, а не в бандле.** `EXPO_PUBLIC_*` инлайнятся при
  сборке, и ключ из `.ipa` или `.apk` достаётся за минуту. Поэтому запросы к
  Anthropic и OpenAI идут через прокси — см. «Прокси».

## Варианты английского

Под языками появляется ряд из трёх вариантов, но только для английского:
британский, американский и кокни. Он меняет словарь, написание и обороты
собеседницы, а расхождения между британским и американским подаются в разборе
как разница вариантов, а не как ошибка.

Кокни живёт по отдельному правилу: собеседница говорит на диалекте, но
**исправляет в сторону литературного английского**. Иначе человек выучил бы
речь, которая работает в одном районе одного города. На уровнях A1–A2 диалект
подаётся самыми лёгкими штрихами — то, чего не понимаешь, ничему не учит.

Произношение при этом не меняется: голоса OpenAI `tts-1` фиксированные, акцент у
них не выбирается. Настоящий британский или кокни в озвучке потребует другого
провайдера — у ElevenLabs такие голоса есть.

## Голос собеседницы

Голос один на все языки — `TTS_VOICE` в `functions/src/index.ts`,
женский `nova` (у Max — выбор из голосов gpt-4o, см. «Подписка и объём»). Раньше на каждый язык стоял свой голос, и на немецком отвечал
мужской `onyx`, хотя на портрете женщина. Голоса OpenAI не привязаны к языку,
так что одна настройка обслуживает всё; `synthesize()` языка не принимает.
Выбор из других голосов tts-1 (`shimmer`, `coral`, `sage`) пробовали и убрали:
на этой модели нормально звучит только `nova`.

В настройках — темп речи: медленнее, обычно, быстрее или «как я»
(подстраивается под темп человека), и под ним размер текста. Раньше оба жили
в профиле, и их не находили. В профиле остались только имя и аватарка.

Провайдер один. ElevenLabs был в спеке ради бесплатных 10k символов в месяц, но
реплика партнёра — около 150 символов, сессия на 15 минут — примерно 3750, и
бесплатный тариф кончается на третьей сессии:

| Режим | Символов/мес | OpenAI | ElevenLabs |
|---|---|---|---|
| 3 раза в неделю | 45k | $0.67 | $22 (Creator) |
| Ежедневно | 112k | $1.69 | $99 (Pro) |
| Ежедневно, 4 языка | 225k | $3.38 | $99 (Pro) |

Разрыв в 30–60 раз: OpenAI берёт $15 за миллион символов, ElevenLabs продаёт
пакетами. Второй провайдер стоил бы второго ключа, второго кода-пути и второго
источника отказов, поэтому его нет.

## Оформление

Две темы, обе снятые с иконки: светлая берёт её холодную половину (фон
`#EFF6FD`, синий акцент `#2E6BD6`), тёмная — индиго нижнего угла (`#0B1046`,
акцент `#5B4BE0`). Обе лежат в `src/theme.tsx`, переключаются солнцем и месяцем
в шапке, выбор сохраняется в AsyncStorage. По умолчанию светлая.

Тема реактивная: компоненты берут её через `useTheme()` и собирают стили
фабрикой `createStyles(theme)` — статический `StyleSheet.create` не переживает
переключения. Все пары текст/фон проверены на контраст, минимум WCAG AA
(на светлом фоне это жёстче: приглушённый текст и голубые подсказки пришлось
затемнить, иначе не проходили).

Значки солнца и месяца нарисованы фигурами, а не символами ☀ и ☾: шрифтовые
глифы выходят разными по весу, а iOS вдобавок подменяет солнце цветным эмодзи.

Главная кнопка не заливается акцентом, а строится на канте: светлый корпус с
сиреневым краем в светлой теме и тёмный с тем же кантом в тёмной. Токены
`ctaBg` / `ctaBorder` / `ctaText`. Кант проверен по порогу 3:1 для границ
элементов, текст — по 4.5:1: в светлой теме 3.83 и 6.21, в тёмной 5.34 и 7.87.

Иконка разложена по `assets/` (`icon.png`, `favicon.png`, adaptive-набор для
Android с фоном `#0B1046`). В Expo Go её не видно — там своя иконка; она
появится в собранном билде.

## Заставка

Портрет во весь экран под гонг, три секунды (`SPLASH_HOLD_MS`), поверх — имя
приложения, а снизу студия, автор и версия из `app.json`. Тап снимает заставку
сразу. Фон под снимком прибит к тёмному, а не взят из темы: в светлой теме перед
загрузкой картинки мелькала белая вспышка.

Нативная заставка (`expo-splash-screen`) настроена по платформам по-разному, и
это не прихоть. На iOS она показывает тот же снимок во весь экран, поэтому
переход к нашей незаметен. На Android начиная с двенадцатой версии заставку
рисует система, и она умеет только иконку в круге — изображение во весь экран
туда поставить нельзя. Поэтому там задан отдельный `android.image` с лицом
крупным планом: в круге оно читается, а портрет целиком человек видит следующим
экраном.

Гонг подрезан ровно под длительность показа, с затуханием в хвосте: иначе звук
обрывался бы на полуслове, когда картинка уже ушла. Резка — тем же приёмом на
AVFoundation, что в KukaViewer.

Держится по таймеру, а не по событию «звук доиграл»: на Android это событие
приходит мгновенно, пока файл ещё грузится, и заставка мигала. Звук —
`assets/splash.m4a` (4 с, скопирован из KukaViewer); чтобы поменять, положите на
его место свой файл. Границы показа в `src/config.ts`: `SPLASH_MIN_MS` (850 —
чтобы заставка не мигнула) и `SPLASH_MAX_MS` (6000 — потолок, если звук не
загрузился).

Нативная заставка Expo настроена в том же цвете `#0B1046`, а её скрытие
отложено до монтирования своей — иначе между ними мелькает белый кадр.

## Персонализация

В профиле задаётся имя и аватарка. Своё фото загружается из галереи или
снимается камерой (`expo-image-picker`), кадрируется квадратом при выборе.
Снимок копируется из временной папки в `Paths.document/avatar/` — иначе система
рано или поздно вычистит кэш и аватарка пропадёт.

Если своего фото нет, есть двенадцать готовых портретов — по четыре мужских,
женских и детских, в `assets/avatars/`, список в `src/avatars.ts`. Фото и
готовая аватарка взаимоисключающие: выбор одного сбрасывает другое, иначе
непонятно, что победит. Пока не выбрано ничего, рисуются инициалы имени.

Имя не украшение: оно уходит в system prompt, и партнёр иногда обращается по
нему — с оговоркой «не в каждой фразе», иначе выходит навязчиво.

У собеседника свои лица, по одному на роль (`assets/tutor*.png`):

| Файл | Когда показывается |
|---|---|
| `tutor.png` | по умолчанию — преподавательница |
| `tutor-clinic.png` | ролевая тема «у врача» |
| `tutor-bank.png` | «в банке» |
| `tutor-repair.png` | «ремонт бытовой техники» |

Карта лежит в `src/components/Avatar.tsx`: Metro требует статических путей в
`require`, собрать имя файла на лету нельзя. Добавить роль — положить картинку и
вписать строку. В архиве лицо берётся из темы той беседы, а не текущей.

## Слова

Раздел «Слова» — тематический список лексики под уровень и тему, как лист,
который учитель раздаёт перед новой темой. Образец — список «Salud, B1»:
части тела, симптомы, у врача, в аптеке, здоровый образ жизни, как спросить о
самочувствии, диалог у врача целиком и предложения-примеры.

**Список составляет модель**, а не лежит в коде: несколько языков на шесть уровней
и три десятка тем — это сотни листов, которые никто не напишет руками. Один
запрос с потолком 16k токенов даёт 80–110 записей в 8–11 группах, диалог на
10–14 реплик и столько же предложений, около сорока секунд и пяти центов.
Объём и характер лексики по уровням задаёт `VOCABULARY_GUIDANCE` в `prompts.ts`:
на A1 сорок самых частых слов, на C1 оттенки между синонимами.

Группы двух видов: «слова» (существительные с артиклем — кроме английского,
глаголы в инфинитиве, сочетания) и «фразы» (готовые предложения для ситуаций
темы). Перевод — на языке интерфейса. Повторы модель просят не делать, а
приложение на всякий случай вырезает само.

**Фразовые глаголы.** В английском с B1 есть третий вид группы — «phrasal»:
экзамены требуют их с этого уровня, и без них не понять живую речь. Идут между
словами и фразами; сколько и каких, задаёт `PHRASAL_GUIDANCE`: на B1 одна
группа самых частых (*look after, find out*), на B2 две, с идиоматическими
значениями и глаголами из трёх частей, на C1–C2 — переносные и разговорные.
Место дополнения видно в самой записи: `put sth off` — можно внутрь,
`look after sb` — нельзя. Из многозначного глагола берётся одно значение —
то, что нужно теме. В тесте фразовый глагол путают только с фразовым.
Старые листы получают группу после «Пересобрать».

**Что можно делать с листом.** Нажатие на слово, реплику или предложение
озвучивает его тем же голосом, что в беседе; озвучка на время сеанса
запоминается, чтобы не платить за повтор. Галочка отмечает выученное — по
языку, а не по листу: «la cabeza» одна и та же в списке о здоровье и о спорте.
Глазик у счётчика «12 / 80» прячет переводы и превращает лист в самопроверку:
перевод открывается нажатием по одной записи. Значок «поделиться» рядом с
темой печатает лист той же формы, что образец, через общий `pdf.ts`.

**Четыре занятия** — список, карточки, повторение, тест — листаются
стрелками под темой: четыре названия в ряд на телефоне не помещались и
резались, а одно показывается целиком; точки под ним говорят, где мы, и
зелёная точка — что в повторении есть подошедшие слова.

**Карточки.** Колода из записей листа, по одной,
нажатие переворачивает карточку. Под словом — транскрипция знаками МФА
(для английского в выбранном варианте, RP или General American), и слово
звучит само, как только показалось: сразу или после переворота; динамик в
углу повторяет. Транскрипцию даёт модель вместе с листом; листам,
составленным раньше, она дописывается одним запросом при первом открытии
карточек. Направление — слово → перевод или
перевод → слово — переключается сверху и запоминается. Под карточкой два
ответа: «знаю» ставит ту же галочку, что в списке, «повторить позже» кладёт
слово в очередь повторения. Уже отмеченные слова колода пропускает.

**Повторение.** Очередь — по языку, а не по листу: слова из разных тем
повторяются вперемешку. Срок у каждой карточки свой: после каждого «знаю»
слово уходит на следующую ступень `REVIEW_INTERVALS` в `review.ts` — десять
минут, день, три, неделя, две, месяц, два, — а «ещё раз» возвращает его на
первую. Прошло всю лестницу — выучено насовсем, уходит из очереди и получает
галочку. Так очередь не разрастается: слова из неё выбывают, а заход берёт не
больше `REVIEW_BATCH` карточек. Если ждут больше `REVIEW_PILE`, раздел
просит повторять понемногу каждый день. О подошедших сроках напоминают
плашка над вкладками и счётчик у «Слов» в меню разделов.

**Тест.** Десять случайных записей листа, к каждой правильный ответ и три
чужих из того же листа — по возможности того же вида, чтобы слово путалось
со словом, а фраза с фразой. Ответ подсвечивается сразу; в конце счёт, список
ошибок и кнопка отложить их на повторение. Собирается на месте, без модели.

**Хранение.** Лист лежит под ключом языка, уровня и темы — второй раз тот же
не составляется, — а список «Мои списки» по языку живёт отдельным индексом.
Всё идёт через общий `write()`, так что попадает в синхронизацию.

**Языки.** Раздел открыт для языков из `VOCABULARY_LANGUAGES` в `config.ts` —
пока английский и испанский; для остальных пункт в меню не показывается.
Генерация языка не знает, так что немецкий и французский подключаются одной
строкой, когда будут проверены.

## Грамматика

Раздел «Грамматика» — программа по ступеням, как оглавление учебника:
A1–A2, B1–B2, C1–C2 (ступень берётся по уровню беседы), внутри — модули и
юниты. Программы лежат в `src/grammar/`:

| Язык | A1–A2 | B1–B2 | C1–C2 | Откуда |
|---|---|---|---|---|
| испанский | 107 | 117 | 106 | курсы Conquistador по Aragonés & Palencia, «Gramática de uso del español» |
| немецкий | 86 | 23 | 24 | A — Wortkraft A2 по перечню Goethe-Zertifikat A2; B — «Grammatik aktiv B2/C1» (Cornelsen), разделы A–G; C — «Übungsgrammatik für die Oberstufe» (Hueber), §§ 1–12 |
| английский | 108 | 103 | 63 | черновик Claude по схеме Murphy (Essential / English Grammar in Use) и Hewings (Advanced) |
| французский | 53 | 44 | 32 | черновик Claude по схеме «Grammaire progressive du français» |
| итальянский | 48 | 37 | 21 | черновик Claude по памяти о Grammatica pratica, Nuovo Espresso и CILS |
| португальский | 22 | 9 | 7 | программы пользователя: A1 (Iniciação) — из первого списка; A2 Plataforma — C2 Maestria — из программы европейского португальского |
| украинский | 69, одним курсом | | | программа подготовительного отделения для иностранцев (722 часа) |
| бразильский португальский | 30, одним курсом | | | программа пользователя A2–C2 (Plataforma … Maestria); A1 — из первого списка тем, переделан под бразильскую норму |

Испанские и немецкие названия и порядок — как в книгах, португальские и
украинские — как в программах пользователя. Английская, французская и
итальянская программы — черновики Claude по памяти о схеме этих учебников,
названия и группировка свои; их стоит заменить, когда будут источники. Ключ юнита — из
ступени и названия (`b:past-perfect`): переименовали тему — урок по ней
составится заново.

**Урок составляет модель** по юниту: две фразы о том, зачем эта структура,
два–пять правил с примерами и переводом, таблица форм, если тема на ней
держится, типичные ошибки и десять упражнений тех же видов, что в домашнем
задании (пропуск, ошибка, перевод) — карточка у них общая. Рассуждение
включено (adaptive, effort medium): без него модель упрощала правила до
неверных — «после in в относительном придаточном всегда Dativ». Урок идёт
около сорока секунд и стоит около четырёх центов, но составляется один раз и
хранится (`polyglotta:grammar:<язык>:<юнит>`); «Новые упражнения» меняют
только задания, передавая модели прежние, чтобы не повторялись. Юнит можно
отметить пройденным; что составлено и что пройдено, лежит отдельно
(`grammarProgress`), чтобы оглавление не читало сотню ключей.

**Связь с беседой.** Домашнее задание по ошибкам получает список юнитов
ступени и называет правило упражнения по названию юнита, если ошибка к нему
относится, — видно, какую тему в «Грамматике» открыть.

## Напоминания

Два напоминания через `expo-notifications`, оба локальные, без сервера:
«повторить слова» дважды в день, утром и вечером, и «время позаниматься»
раз в день. Все три времени человек выбирает стрелками в настройках по
полчаса; по умолчанию 10:00, 19:00 и 18:00. Оба включены по
умолчанию, выключаются нажатием на строку.

Над ними — общий выключатель «Уведомления и напоминания» (`enabled` в
`ReminderSettings`). Выключен — расписание снято, разрешение не спрашивается,
строки времени скрыты, но выбранные времена сохраняются до включения. В
настройках прежних версий поля нет — это «включено».

Расписание живёт в системе, поэтому `syncReminders()` приводит его к
настройкам заново — снимает всё и ставит нужное — при каждом запуске, при
смене настроек и когда очередь повторения пустеет или впервые наполняется:
напоминать о словах, которых нет, незачем. Разрешение спрашивается в тот
момент, когда есть что напоминать; если его нет, строки в настройках
говорят, что уведомления выключены в системе. В Expo Go на Android
уведомления не работают — нужна сборка.

## Экзамен B1 и B2

Раздел «Экзамен» — устная часть экзамена B1 или B2 голосом: экзаменатор здоровается,
задаёт несколько вопросов о человеке, даёт задание на монолог и ведёт
обсуждение. По ходу он ничего не исправляет и не хвалит, как на настоящем
экзамене; разбор приходит одним запросом по всей стенограмме в конце.

**Уровень.** Переключатель B1 / B2 в шапке раздела; выбор хранится отдельно по
языку (`polyglotta:examLevel:<язык>`), а пока его не трогали, берётся ближайший
к уровню беседы: до B1 включительно — B1, выше — B2. Темы на обоих уровнях одни,
меняются формат, план частей, речь экзаменатора и мерка разбора. Уровень
сохраняется в сессии, поэтому старая сессия из истории разбирается по своему.

**Формат по уровням и языкам.** Три части у всех экзаменов по сути одни и те же
— вопросы о себе, монолог, разговор, — а различаются формой монолога и
разговора. Их и описывает `EXAM_FORMATS` в `src/exam.ts`:

| Уровень | Язык | Похож на | Монолог | Разговор |
|---|---|---|---|---|
| B1 | en | Cambridge B1 Preliminary | описать сцену (вместо фотографии) | выбрать лучший из вариантов |
| B1 | de | Goethe-Zertifikat B1 | Teil 2: презентация по пяти пунктам | Teil 1: спланировать что-то вместе |
| B1 | fr | DELF B1 | point de vue по короткому тезису | ролевая сцена (interaction) |
| B1 | es | DELE B1 | Tarea 1: presentación de un tema | Tarea 4: situación simulada |
| B2 | en | Cambridge B2 First | сравнить две ситуации (вместо фотографий) | мнение по широким вопросам |
| B2 | de | Goethe-Zertifikat B2 | Vortrag: ситуация, опыт, за и против | Diskussion |
| B2 | fr | DELF B2 | monologue suivi: позиция по тезису | débat |
| B2 | es | DELE B2 | valorar propuestas | conversación |

В Goethe B1 планирование в настоящем экзамене идёт первым, а в DELF B1 точка
зрения — последней; здесь порядок у всех один, и описание части прямо говорит
модели, что он изменён.

Язык и уровень живут только в этом файле: названия тем, имя экзамена, описание
частей, план. Промпты, хуки и экраны от них не зависят — новая тема, язык или
уровень добавляются там же.

**Части считает приложение, а не модель.** `EXAM_PLANS`: три ответа на
знакомство, два на монолог (сам монолог и вопрос по нему) и четыре на разговор
у B2, три — у B1: на этом уровне четвёртый круг о том же превращается в повтор. К каждому ответу человека в запрос добавляется пометка «это ответ 2
из 3 в знакомстве, задай следующий вопрос» или «закрой часть и дай задание на
монолог». Пометка идёт вторым блоком последней реплики и в сохранённую
стенограмму не попадает — начало запроса не меняется, и кэш промпта работает
как в беседе. Модель, которой сказали «переходи, когда сочтёшь нужным», то
застревает на знакомстве, то проскакивает монолог.

**Голосовой цикл общий с беседой.** Шкала пауз настраивалась десятком коммитов,
поэтому запись, определение конца реплики, Whisper, озвучка и воспроизведение
вынесены из `useConversation` в `useVoiceLoop`. Беседа и экзамен отличаются
только тем, что делают с распознанным текстом. У экзамена свои пороги: ответ
до трёх минут (`EXAM_MAX_TURN_MS`, монолог в DELE идёт две-три) и пауза 2,5 с
вместо 1,3 (`EXAM_SILENCE_HOLD_MS`) — в монологе останавливаются подумать. На
время монолога экран советует выключить AUTO.

**Разбор.** `reviewExam` в `llm.ts` возвращает JSON по схеме: ошибки с полями
`original`, `corrected`, `explanation`, `category` (`grammar` / `vocabulary` /
`collocation` / `fluency`) и две-три рекомендации. Счёт по категориям считается
в коде по списку, а не просится у модели, — иначе цифры расходились бы со
списком под ними. Как и в письме, ошибка без дословной цитаты из ответов
человека до экрана не доходит. Пояснения — на языке интерфейса.

**История.** Сессия сохраняется с первого ответа и после каждого следующего,
тремя ключами: строка списка, реплики, разбор. Перезапуск или обрыв сети не
стоят ответов, а разбор можно запросить заново из истории. Ключи идут через
общий `write()`, поэтому попадают и в синхронизацию; раздельные ключи держат
каждый документ Firestore далеко от предела в 1 МБ.

**Лимит.** Экзамен стоит как беседа и считается тем же дневным лимитом
`FREE_TALKS_PER_DAY`; запросы идут через тот же счётчик расхода. Пока идёт
беседа, экзамен не начинается — микрофон один; пока идёт экзамен, домик скрыт.

## Домашнее задание

По итогам беседы приложение собирает упражнения из её же ошибок: строка
«Задание» в панели, кнопка «Составить задание». В модель уходит список
исправлений, обратно приходит структурированный разбор — две-три фразы о том,
над чем работать, и пять-десять упражнений трёх видов:

| Вид | Что делает |
|---|---|
| `fill` | вставить слово в пропуск |
| `fix` | найти ошибку в предложении |
| `translate` | перевести фразу на изучаемый язык |

Упражнения связаны с беседой в обе стороны. Модель возвращает номер ошибки, из
которой выросло упражнение; номер тут же разрешается в текст пары «сказал →
правильно» и хранится прямо в упражнении — задание уезжает в архив и должно
читаться само, без обращения к той беседе. В карточке эта пара показана строкой
«Из беседы», а в ленте исправления, попавшие в задание, помечены «в задании».

В промпте прямо запрещено брать предложения из беседы: те же правила, но новые
фразы, иначе запоминается ответ, а не правило. Ответ в карточке скрыт, пока его
не откроют, — иначе глаз цепляет его раньше, чем голова успевает подумать.

Задание живёт вместе с беседой: при уходе в архив переезжает под её
идентификатор и открывается из архива кнопкой «Задание», в списке беседа
помечается «с заданием». Это отдельный вызов модели с потолком 8192 токена —
роль другая, не собеседник, а преподаватель.

## Размер текста

В настройках три размера: обычный, крупный, очень крупный (раньше были в
профиле, рядом с именем, и их не находили). Масштаб живёт в теме, и
стили каждого компонента прогоняются через `useStyles` — тот сам растягивает
`fontSize` и `lineHeight` в готовых правилах. Иначе множитель пришлось бы
вписывать в каждое правило вручную, и любое новое неизбежно про него забыло бы.

## Экспорт задания в PDF

Кнопка «PDF» в шапке задания собирает документ и отдаёт его в системное окно
«Поделиться». Порядок разделов: заголовок беседы, диалог целиком с разбором
ошибок, задания с местом для ответа, и ответы — **отдельной страницей в конце**
(`page-break-before`). Иначе взгляд цепляет ответ раньше, чем успеваешь подумать
над упражнением.

Разметка вынесена в `homeworkHtml.ts` без нативных импортов: её можно собрать и
проверить обычным Node, не поднимая симулятор. Весь текст, попадающий в HTML,
экранируется — туда идут реплики человека и ответ модели.

## Архив

Законченная беседа не стирается, а уходит в архив — кнопка со значком коробки в
шапке, рядом с переключателем темы. Причина проста:
разбор ошибок и есть то, ради чего к беседе возвращаются. Метаданные списка
(язык, уровень, тема, даты, число реплик и ошибок, первая фраза) лежат одним
ключом, реплики — отдельным на беседу, и грузятся только при открытии. В архиве
беседа читается целиком, вместе с исправлениями и грамматикой под «?».

## Планшеты

Колонка контента ограничена `CONTENT_MAX_WIDTH` (640) и центрируется: на
тринадцати дюймах лента во всю ширину дала бы строки, которые неудобно читать.
Кнопки языка и уровня группируются по центру панели, а не расползаются по краям.
Поворот разрешён (`orientation: default` в `app.json`) — на планшете портретная
блокировка неуместна. Проверено на iPad Pro 11".

На планшете телефонные размеры терялись на пустом экране, поэтому интерфейс
там крупнее — тем сильнее, чем больше экран. Класс устройства — по короткой
стороне экрана (`DEVICE_CLASS` в `src/layout.ts`): она не меняется при повороте
и не зависит от Split View.

| Класс | Устройства | Интерфейс | Кнопки шапки | Портрет |
|---|---|---|---|---|
| phone (< 600) | iPhone | 1 | 1 | 1 |
| tablet7 (600–799) | iPad mini, Android 7–8" | 1,15 | 1,5 | 1,8 |
| tablet11 (800–999) | iPad 11" | 1,25 | 1,75 | 2,2 |
| tablet13 (≥ 1000) | iPad 13" | 1,4 | 2 | 2,5 |

«Интерфейс» (`UI_SCALE`) применяет `useStyles`: размеры, отступы, скругления и
шрифты всех стилей, включая колонку `CONTENT_MAX_WIDTH`; рамки остаются
тонкими. Значки (`icons.tsx`) масштабируются сами. Кнопки шапки и портрет
крупнее общего масштаба — они главные на пустом экране. Числа для 13"
подобраны на iPad Pro 13" (кнопки в 4 раза и портрет в 6 оказались слишком
крупными), 11" и 7" — пропорционально. Шапка беседы и кнопка беседы вынесены
из колонки ленты: у них своя ширина. В альбомной ориентации портрет не выше
40 % экрана; по тапу на планшете он не раскрывается. Меню разделов на планшете
ещё крупнее — посередине между интерфейсом и кнопкой шапки. Проверено в
симуляторах iPad mini, iPad Pro 11" и 13".

Меню разделов — панель, выезжающая слева из-за края экрана на высоте домика;
закрывается тем же движением обратно.

### Сцены на iOS 27

Приложение, собранное Xcode 27, на устройстве падает сразу на запуске в
`_UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`: SDK iOS 27
требует жизненный цикл UIScene, а шаблон Expo 57 ещё создаёт окно в
AppDelegate (expo/expo#46664, #50179; сцены штатно — в SDK 58). На симуляторе
та же сборка запускалась, поэтому падение заметили только на iPad.

Чинит `plugins/withSceneLifecycle.js`: манифест сцен в Info.plist, AppDelegate
только запоминает `launchOptions`, а `SceneDelegate` создаёт окно из сцены,
запускает React Native и передаёт ему ссылки, с которыми открыли приложение, —
иначе dev-client не находит Metro, а deep links теряются. Одного манифеста
мало: без окна из сцены экран чёрный. Плагин падает с ошибкой, если шаблон
AppDelegate изменится, — чтобы не собрать молча приложение без окна. После
перехода на SDK 58 его надо убрать.

`ios.appleTeamId` в `app.json` — команда для подписи: `ios/` пересоздаётся
пребилдом, и выбранный в Xcode Team терялся бы каждый раз.

## Нижний край экрана

Кнопка беседы — плоская полоса во всю ширину внизу. Она лежит внутри
`SafeAreaView` с `edges={['top', 'bottom']}`, поэтому системный отступ снизу
приходит из инсетов, а не из константы: при трёхкнопочной навигации под кнопкой
остаётся 153 px, при жестовой — 90 px, и перекрытия нет в обоих режимах.
Проверено на эмуляторе Android с переключением обоих режимов.

## Что Whisper не доносит до разбора

Прогон на живых ключах показал: Whisper подменяет выдуманные формы слов на
ближайшие настоящие. Сказанное `I buyed` приезжает как `I buy`, и ошибка до
разбора не доходит.

Проверено, что проблема узкая. В одной фразе с ошибками разных типов —
`I go` вместо `went`, `I have not my passport`, `more cheaper`,
`How much documents I need` — уцелело всё. Не выживают только несуществующие
словоформы, которые звучат как реальное слово.

Подсказка Whisper с просьбой расшифровывать дословно результата не дала —
пробовал, не помогло, поэтому в коде её нет. Часть эффекта, вероятно, от самой
проверки: там речь синтезирована TTS, а живое произношение отчётливее.

## Заплатка на expo-modules-jsi

`ExpoModulesJSI` из Expo SDK 57 не собирается компилятором Swift 6.2 из
Xcode 26.2: три ошибки вида «sending 'argumentsPtr' risks causing data races» в
`JavaScriptRuntime.swift`. Подпись API объявлена через `sending`, поэтому
понижение языкового режима до Swift 5 не помогает — пробовал, ошибки остаются.

Заплатка в `patches/expo-modules-jsi+57.0.8.patch` везёт адреса указателей
целым числом (`UInt(bitPattern:)`), а на месте использования восстанавливает их
через `unsafeBitCast`. Целое отправлять между изоляциями можно, поэтому цепочка
проверок рвётся, а семантика не меняется. Накатывается автоматически:
`patch-package` прописан в `postinstall`.

Важно: **`unsafeBitCast`, а не `UnsafePointer(bitPattern:)!`**. При вызове
JS-функции без аргументов JSI передаёт нулевой указатель, optional-инициализатор
возвращает на нём `nil`, и принудительное развёртывание роняет процесс уже во
время работы, а не сборки.

Обновляться до `expo-modules-jsi@57.1.0` не нужно: там возвращается
`SWIFT_RETURNS_RETAINED` в `RuntimeScheduler.h`, который тот же Xcode тоже
отвергает. В установленном 57.0.8 этой аннотации нет.

## Отправка записи в Whisper

Запись уходит на прокси телом запроса как есть — байтами из `file.bytes()`,
язык в строке запроса. Форму для OpenAI собирает сервер. Так приложению не
нужен `FormData`, с которым у `fetch` Expo свои счёты: он принимает в форму
только строку, `Blob` или объект с методом `bytes()`, а привычный для React
Native `{ uri, name, type }` отвергает с «Unsupported FormDataPart
implementation».

## Прокси

Ключей Anthropic и OpenAI в приложении нет. Они лежат в Secret Manager проекта
Firebase, и видит их только функция `api` (`functions/src/index.ts`, регион
`europe-west1`). Приложение ходит к ней по трём маршрутам:

| Маршрут | Что делает |
|---|---|
| `/claude/v1/messages` | Anthropic SDK с `baseURL` на прокси; модель и потолок токенов сервер проверяет сам |
| `/transcribe?language=xx` | Whisper; длительность для учёта — из ответа `verbose_json` |
| `/speak` | озвучка `tts-1`, голос `nova` задан на сервере |

Каждый запрос несёт Firebase ID-токен (`src/services/proxy.ts`). Кто не
заводил аккаунт, входит анонимно и незаметно для себя: серверу нужно знать,
чей расход и чья подписка. Регистрация превращает анонимный вход в аккаунт
(`linkWithCredential`), так что uid, подписка и расход не теряются. Для
интерфейса и синхронизации анонимный вход — это «без аккаунта».

Ключ поменять — `npx firebase-tools functions:secrets:set ANTHROPIC_API_KEY`
(или `OPENAI_API_KEY`) и `npx firebase-tools deploy --only functions`;
приложение пересобирать не нужно. `REVENUECAT_SECRET_KEY` пока `none`:
магазины не настроены, и сервер, как и приложение, даёт всем объём Pro.

## Нет сети

Без интернета каждый слой падает по-своему: fetch у React Native и Expo пишет
«Network request failed», Anthropic SDK — «Connection error.», iOS —
NSURLErrorDomain -1009, Android — UnknownHost, Firebase —
auth/network-request-failed. Человеку эти строки ничего не говорят, поэтому
все ошибки перед показом проходят через `errorText()` (`src/errors.ts`): она
узнаёт сетевой сбой и показывает одну фразу — «Приложение офлайн: нет
подключения к интернету». Остальные ошибки выводятся как были.

## Подписка и объём

Три тарифа (`Tier` в `src/config.ts`):

- **без подписки** — одна короткая беседа в день (8 реплик, `FREE_TURNS_PER_TALK`) и месячный объём 1,5 $;
- **Pro, 5 €** — без дневного лимита, объём 3 $ (20–30 бесед);
- **Max, 7 €** — объём 5 $ (35–45 бесед) и голоса gpt-4o на выбор.

Беседа — самая дорогая часть, а голоса gpt-4o-mini-tts стоят примерно на
четверть дороже tts-1 (около $0.017 против $0.014 за минуту), поэтому и то и
другое — в Max. Голоса Max: `nova`, `coral`, `sage`, `marin` (`MAX_VOICES`);
`shimmer` в этой модели на испанском звучит по-мужски, его нет. Подача задана
инструкцией — тёплая, разговорная; с ней делались пробы, которые понравились.
Без Max голос один — `nova` на tts-1: другие голоса tts-1 звучат хуже. В
настройках голоса Max видны всем, но выбрать и послушать их можно только в Max,
у остальных нажатие открывает тарифы.

Цены задаются не в коде, а в магазинах: два продукта в App Store Connect и
Google Play. В RevenueCat Pro привязан к праву `pro` (`PRO_ENTITLEMENT`), Max —
к `max` и `pro` сразу (`MAX_ENTITLEMENT`), оба в текущем предложении. Пейвол
отличает Max по идентификатору продукта — в нём должно быть «max»
(`MAX_PRODUCT_MARK`, например `poly_max_monthly`). Приложение получает от
RevenueCat готовую строку с ценой в валюте магазина и показывает её как есть. В
`src/config.ts` цены (`TIER_PRICE_EUR`) записаны только как точка отсчёта для
объёма.

Объём — это контроль токенов. Каждый запрос к API переводится в доллары по
ценам провайдеров (`CLAUDE_PRICE`, `WHISPER_PRICE_PER_MINUTE`,
`TTS_PRICE_PER_CHAR`) и складывается в месячный итог (`src/services/meter.ts`,
ключ `polyglotta:spend`). Claude сам отчитывается о токенах, включая кэш;
озвучка считается по символам; для Whisper длительность выводится из размера
файла по битрейту записи — рекордер отдаёт её не везде. Перед каждым запросом
итог сверяется с объёмом тарифа — `MONTHLY_BUDGET_USD`: Max 5 $, Pro 3 $, без
подписки 1,5 $.

Бесплатная беседа короткая: на восьмой реплике человека (`FREE_TURNS_PER_TALK`)
к запросу добавляется записка для модели — ответить коротко и тепло
попрощаться, — а флаг прощания выставляется принудительно, так что беседа
закрывается, даже если модель забыла. Под лентой появляется плашка с кнопкой
подписки. Раньше при объёме 1 $ и «одной беседе в день» полной длины объём
кончался примерно через неделю ежедневных занятий, и обещание «одна беседа в
день» не выполнялось: беседа на 15 реплик стоит $0.10–0.15, на 8 — около
$0.05, и 1,5 $ хватает на месяц. Лимит реплик ставит App по тарифу; у
подписки и в unlim-сборках его нет.
Когда объём исчерпан, запрос не уходит, а на экране появляется «Месячный объём
исчерпан». Считается календарный месяц, а не месяц с покупки: дату продления
без сети не спросить, а календарь есть всегда.

Решает сервер. Прокси ведёт месячный расход по uid в Firestore (`spend/{uid}`),
считая по тем же ценам (озвучку Max — по длительности mp3), и узнаёт тариф в
RevenueCat; он же выбирает модель озвучки; когда объём
исчерпан, отвечает 402, и приложение показывает то же «Месячный объём
исчерпан». Счётчик на телефоне остался для экрана — доли объёма на
пейволе. Дневной лимит бесед по-прежнему живёт на устройстве. Слабое место —
анонимный вход: переустановка даёт новый uid и новый бесплатный объём; от
этого защитит App Check.

## Итальянский, португальский и украинский

Языки изучения — английский, немецкий, французский, испанский, итальянский,
португальский и украинский (`LanguageCode`). Новые два встроены по образцу испанского:
метаданные в `languages.ts`, темы в `topics.ts` (29 общих, своя местная —
кухня и кофе у итальянского, фаду и паштел-де-ната у португальского — и четыре
ролевые), экзамены в `exam.ts`, программы грамматики в `src/grammar/it.ts` и
`pt.ts`.

Португальский — европейский. Под него есть экзамены по шкале CEFR — CAPLE:
DEPLE на B1, DIPLE на B2; у бразильского Celpe-Bras своя шкала. Во всех
промптах язык называется «European Portuguese» (`englishName`), иначе модель
сбивается на бразильский: «estar fazendo» вместо «estar a fazer», «você» вместо
«tu». Итальянский экзамен — в духе CILS: UNO-B1 и DUE-B2.

Португальская программа — от пользователя: A1 (Iniciação) — из первого
списка тем, A2 (Plataforma), B1 (Limiar), B2 (Vantagem), C1 (Autonomia) и C2
(Maestria) — из программы европейского португальского; 38 юнитов, подгруппы
внутри уровня — отдельные модули. Итальянская — пока черновик Claude по
памяти, с официальными перечнями не сверен; заменить её стоит программой по
Profilo della lingua italiana или силлабусу CILS — так же, как испанский стоит
на Conquistador. Раздел «Слова» для обоих пока закрыт (`VOCABULARY_LANGUAGES`),
как для немецкого и французского: открывается одной строкой после проверки.

Украинский добавлен следом тем же путём (местная тема — борщ, вишиванка и
народные песни), но грамматика у него — один сквозной курс без ступеней
A/B/C, как учат украинский как иностранный: по программе подготовительного
отделения для студентов-иностранцев (722 часа; учебник Чистяковой,
Селіверстової, Лагути, ХНУ). 69 юнитов в девяти модулях — от фонетики через
«вираження місця / часу дії» к сложным предложениям и словообразованию.
`src/grammar/uk.ts` — список модулей, а не ступени; `isSingleCourse()` в
`src/grammar/index.ts` показывает его при любом уровне, вместо «A1–A2» на
экране — «Весь курс». Ключи юнитов теперь сохраняют кириллицу: раньше они
брали только латиницу, и все украинские ключи выходили пустыми. Единого международного бренда экзамена, как
Goethe или DELE, у него нет, поэтому формат назван просто «Українська як
іноземна» и описан в духе сертификатных экзаменов: вступительная беседа,
монолог, диалог в ситуации или дискуссия. Экзамен, как и грамматика, один —
без переключателя B1/B2 (`examHasLevels`); сложность вопросов и строгость
разбора берутся из уровня беседы и на экране не показываются. Код `uk` у языка изучения и
у языка интерфейса совпадает, но это разные типы (`LanguageCode` и `UiLocale`).

У бразильского португальского и украинского уровней нет: оба — один
сквозной курс (`isSingleCourse`), в настройках ряд A1–C2 для них скрыт.
Бразильская программа — те же модули от A1 до C2 подряд; буквы ступеней в
`module()` оставлены, чтобы ключи юнитов и написанные уроки не менялись.
Уровень для сложности беседы и диктантов берётся сохранённый (по умолчанию
B1).

Бразильский португальский — отдельный язык изучения (`br`, 🇧🇷 «Brasileiro»),
а не вариант европейского: другая норма (você, герундий вместо «estar a»,
проклиза в начале фразы), своя программа (`src/grammar/br.ts`) и свой экзамен —
Celpe-Bras. У Celpe-Bras нет отдельных экзаменов B1 и B2 — уровень ставится по
результату, поэтому экзамен, как у украинского, один. В промптах — «Brazilian
Portuguese», Whisper получает «pt» (`whisper` в `languages.ts`).

В настройках восемь флажков стоят сеткой по четыре в ряд: в одну строку плитки
прежнего размера не влезают.

## Языки интерфейса

Десять: английский, украинский, испанский, русский, немецкий, французский,
португальский, китайский (упрощённый), японский и корейский (`UiLocale` в
`src/i18n.ts`). Язык берётся с устройства через
expo-localization; незнакомый — английский. На нём же пишутся разборы ошибок,
правила и переводы слов (`EXPLANATION_LANGUAGE_NAME`), так что перевод
интерфейса — это и язык объяснений, а не только подписи кнопок.

Немецкий и французский добавлены ради самого платёжеспособного рынка: немцы и
французы учат английский и испанский, а объяснения им раньше шли по-английски.
Немецкий — на «du», как принято в приложениях; французский — на «vous».
Названия тем и тем экзамена на этих языках взяты из самих немецкого и
французского списков тем, дописаны только местные темы других языков.

Португальский интерфейс — бразильский, на «você»: устройство сообщает только
`pt`, без страны, а бразильцев среди изучающих языки намного больше, чем
португальцев, и бразильский вариант понятен и тем и другим. Объяснения идут на
«Brazilian Portuguese». Это не спорит с португальским как языком изучения — тот
европейский (см. выше): интерфейс и изучаемый язык — разные вещи.

Китайский, японский и корейский добавлены для азиатских рынков изучения
английского. Китайский — упрощённые иероглифы на «你», японский — вежливый
です/ます, корейский — 해요체. Имя героини — 波莉夫人 и マダム・ポリー, а
по-корейски — 폴리 선생님 («учительница Поли»): 마담 по-корейски прежде всего
хозяйка чайной или бара, с сомнительным оттенком. 保利 для «Poly» не годится —
так пишется название китайской госкорпорации Poly Group. Устройство сообщает
только `zh`, поэтому упрощённый китайский получат и телефоны Тайваня и
Гонконга, где пишут традиционными иероглифами.

Языки объявлены и в `app.json`: `supportedLocales` плагина expo-localization
— список языков, из которого iOS и Android дают выбрать язык приложения в
системных настройках, а `locales` — файлы `locales/*.json` с переводом
системных окон (микрофон, фото, камера) и названия. Раньше системные окна были
только по-английски и со старым названием «Madame Polyglotta».

Новый язык: строки в `i18n.ts` (тип `Strings` не даст пропустить ключ),
`GLOSSES` в `topics.ts` и `exam.ts`, а ещё лендинг и описание в магазинах.

## Настройки

Всё, что стоит крутить, — в `src/config.ts`: модель, потолок токенов, провайдер
озвучки, длина окна истории, автовоспроизведение ответа. Язык объяснений
следует за языком интерфейса.
