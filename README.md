# Madame Poly

Личное приложение для голосовой практики разговорной речи на английском, немецком,
французском и испанском. Говоришь → Whisper распознаёт → Claude отвечает и разбирает
ошибки → ответ озвучивается.

Исходная спека: [`docs/Polyglotta.pdf`](docs/Polyglotta.pdf).

## Запуск

```bash
cp .env.example .env      # подставить ключи OpenAI и Anthropic
npm install
npm run go                # Expo Go
```

Нативные проекты сгенерированы и лежат в `ios/` и `android/` (в git не
попадают — их всегда можно пересобрать):

```bash
npx expo prebuild --platform all --clean   # пересобрать оба
npm run android                            # сборка и запуск Android
npm run ios                                # сборка и запуск iOS
```

`npm run ios` в этом окружении не соберётся — см. раздел об ограничениях.

Микрофон недоступен в Expo Go на web — запускать на устройстве или симуляторе
(`i` / `a` в терминале Expo).

### Проверка ключей и промпта без UI

```bash
npm run smoke            # английский, B1
npm run smoke -- de A2   # немецкий, A2
```

Скрипт озвучивает фразу с намеренными ошибками, распознаёт её обратно через
Whisper и отдаёт Claude — за один прогон проверяются оба ключа, system prompt и
структурированный разбор ошибок, не трогая симулятор. Использует настоящие
`src/prompts.ts` и `src/services/llm.ts`, так что расхождения с приложением нет.

Кто ведёт реплику, переключает кнопка «АВТО» слева от главной полосы.
Подсвечена — приложение ловит паузу само и сразу слушает дальше.

Погашена — реплику ведёте вы целиком: после ответа собеседницы микрофон не
открывается, полоса показывает «Ответить» и ждёт нажатия. Так и задумано:
человеку нужно время прочитать ответ и придумать свой, а не отвечать сразу после
гудка. Нажали — пошла запись, полоса стала «Готово»; беседа закрывается долгим
нажатием. Ручной
режим нужен тем, кто говорит медленно: авто режет фразу на первой же паузе.

Отдельной строки под выбор режима нет намеренно — на маленьком экране высота
дороже. Во время беседы кнопка заблокирована: смена режима на полуслове сбила бы
запись. Потолок реплики `MAX_TURN_MS` работает в обоих режимах.

Осциллограмма входа рисуется фоном внутри главной полосы: видно, открыт ли
микрофон, и это не занимает отдельной панели. Портрет собеседницы стоит в центре
шапки, вровень со строкой языка.

Дальше — про авторежим. Беседа идёт без тапов, как в Loora: нажал «Начать беседу» — приложение слушает,
по паузе в речи само заканчивает реплику, отвечает голосом и снова слушает.
Границу реплики определяет по уровню входного сигнала (`isMeteringEnabled` у
рекордера), пороги вынесены в `src/config.ts`:

Порог речи не абсолютный, а отсчитывается от шума комнаты и обновляется всю
беседу: фон меряется по паузам между словами. Разовая калибровка в начале не
годилась — тихая музыка или улица могут появиться на середине разговора.

Фон падает мгновенно и поднимается плавно (`NOISE_RISE`), а во время речи ползёт
вверх на порядок медленнее (`NOISE_RISE_SPEECH`). Второе — страховка: если шум
появился громче текущего порога, он будет принят за речь, и без медленного
подъёма оценка фона застыла бы навсегда. С ним приложение выбирается само,
примерно за пятнадцать секунд.

Замеренный фон зажат между `NOISE_FLOOR_MIN_DB` и `NOISE_FLOOR_MAX_DB`, чтобы
оценка не уехала в потолок и приложение не оглохло.

| Константа | По умолчанию | Что делает |
|---|---|---|
| `SPEECH_LEVEL_DB` | `-35` | нижняя граница порога: ниже он не опускается |
| `NOISE_MARGIN_DB` | `12` | насколько порог выше шума комнаты |
| `NOISE_RISE` | `0.05` | как быстро фон растёт на паузах |
| `NOISE_RISE_SPEECH` | `0.002` | то же во время речи — страховка от шума |
| `NOISE_FLOOR_MIN_DB` / `MAX` | `-60` / `-40` | границы доверия к замеру |
| `SILENCE_HOLD_MS` | `1300` | сколько тишины после речи завершает реплику |
| `MIN_SPEECH_MS` | `400` | минимум речи, чтобы не реагировать на шум |
| `MAX_TURN_MS` | `30000` | жёсткий потолок одной реплики |
| `METERING_INTERVAL_MS` | `100` | как часто опрашивать уровень |

Если пауза всё равно не ловится, поднимайте `NOISE_MARGIN_DB`; если реплику
обрывает на середине — снижайте его или увеличивайте `SILENCE_HOLD_MS`.

Если реплика оказалась шумом, а не речью, она не уходит в Whisper — приложение
молча слушает дальше. Под панелью языка стоит полоса с лицом собеседника слева
и осциллограммой входа справа: пока микрофон открыт, полоски дышат по громкости
и подпись говорит «Слушает»; как только приложение распознаёт, думает или
отвечает, линия выпрямляется. Без неё в режиме свободных рук непонятно, слышно
тебя сейчас или нет.

Беседа заканчивается сама, когда человек прощается: модель возвращает признак
`farewell` вместе с ответом, приложение даёт прощальной реплике доиграть и
закрывает сессию, а не уходит слушать снова. В промпте отдельно оговорено, что
пауза, короткий ответ или смена темы прощанием не считаются.

Тап по портрету увеличивает его, осциллограмма при этом становится короче.
Число полосок не задано числом, а считается по фактической ширине панели —
поэтому оно само подстраивается и под раскрытый портрет, и под планшет.

### Темы разговора

Если своей темы нет, в панели выбирается готовая — по тридцать четыре на язык в
`src/topics.ts`, с названием на изучаемом языке и переводом для быстрого выбора.
Двадцать девять тем общие, тридцатая своя у каждого языка: британский против
американского, Октоберфест, сыр и вино, фламенко.

Ещё четыре — ролевые ситуации: в банке, в аптеке, у врача с простудой и звонок
в сервис по ремонту бытовой техники. У них другой режим: партнёр играет
сотрудника, а не расспрашивает о впечатлениях, и описание сцены лежит в
`ROLEPLAY_SCENES` — по одному на ситуацию, а не на язык, потому что роль одна и
та же. В промпте для них своя ветка, и первая реплика тоже звучит в роли.

Готовых первых фраз в списке нет намеренно: одна и та же заготовка звучала бы
одинаково и на A1, и на C1. Тема уходит в system prompt, а открывающую реплику
партнёр придумывает сам под уровень и сразу её озвучивает. Выбор темы хранится
отдельно по каждому языку, «Свободная» возвращает обычный разговор.

Язык и уровень собраны в одну панель квадратных кнопок под шапкой. Она прячется
сама через `PANEL_AUTOHIDE_MS` (5 с) бездействия и сразу при старте беседы —
дальше она только отнимает место у ленты. В свёрнутом виде остаётся строка
«🇬🇧 English · B1», по тапу панель разворачивается обратно.

Язык и уровень — параметры, а не отдельные экраны: один system prompt обслуживает
все четыре языка, уровень хранится отдельно по каждому и регулирует сложность речи ИИ.

Ответ Claude приходит структурированным (`{ reply, corrections[] }`) через
structured outputs, поэтому реплика и разбор ошибок не смешиваются: `reply` уходит
в озвучку, `corrections` показываются под сообщением пользователя.

Каждое исправление состоит из четырёх частей: `original` и `corrected` —
что было и как правильно, `explanation` — одна строка на виду, `rule` и
`details` — название правила и разбор на две-четыре фразы с ещё одним примером.
Последние два прячутся за «?» рядом с пузырём: во время беседы грамматика
отвлекает, а после — это единственное, ради чего стоит вернуться к ленте.

## Решения по открытым вопросам из спеки

| Вопрос | Решение |
|---|---|
| OpenAI TTS или ElevenLabs | OpenAI `tts-1` — тот же ключ, что у Whisper. ElevenLabs вырезан: его бесплатные 10k символов кончаются на третьей сессии, а дальше он выходит в 30–60 раз дороже (см. «Голос собеседницы»). |
| System prompt партнёра | `src/prompts.ts`: роль, правила для устной речи, отдельные правила для разбора ошибок, поведение по каждому уровню CEFR. |
| Streaming в первой версии | Нет. Реплики короткие (1–3 предложения), а озвучка всё равно ждёт полного текста — выигрыш был бы небольшим. |
| Где хранить историю | Локально, AsyncStorage. Firebase не нужен: приложение личное и одноустройственное. |

## Отличия от спеки

- **`expo-audio` вместо `expo-av`.** `expo-av` удалён в SDK 55+; проект на SDK 57.
- **Ключи API лежат в бандле.** Для личной сборки это приемлемо; при публикации
  понадобился бы прокси-бэкенд, потому что `EXPO_PUBLIC_*` инлайнятся при сборке.

## Варианты английского

Под языками появляется ряд из трёх вариантов, но только для английского:
британский, американский и кокни. Он меняет словарь, написание и обороты
собеседницы, а расхождения между британским и американским подаются в разборе
как разница вариантов, а не как ошибка.

Кокни живёт по отдельному правилу: собеседница говорит на диалекте, но
**исправляет в сторону литературного английского**. Иначе человек выучил бы
речь, которая работает в одном районе одного города. На уровнях A1–A2 диалект
подаётся самыми лёгкими штрихами — то, чего не понимаешь, ничему не учит.

Произношение при этом не меняется: голоса OpenAI `tts-1` фиксированные, акцент у
них не выбирается. Настоящий британский или кокни в озвучке потребует другого
провайдера — у ElevenLabs такие голоса есть.

## Голос собеседницы

Голос один на все четыре языка — `OPENAI_TTS_VOICE` в `src/config.ts`, по
умолчанию женский `nova`. Раньше на каждый язык стоял свой голос, и на немецком
отвечал мужской `onyx`, хотя на портрете женщина. Голоса OpenAI не привязаны к
языку, так что одна настройка обслуживает всё. Поэтому `synthesize()` больше не
принимает язык — параметр был бы мёртвым.

Провайдер один. ElevenLabs был в спеке ради бесплатных 10k символов в месяц, но
реплика партнёра — около 150 символов, сессия на 15 минут — примерно 3750, и
бесплатный тариф кончается на третьей сессии:

| Режим | Символов/мес | OpenAI | ElevenLabs |
|---|---|---|---|
| 3 раза в неделю | 45k | $0.67 | $22 (Creator) |
| Ежедневно | 112k | $1.69 | $99 (Pro) |
| Ежедневно, 4 языка | 225k | $3.38 | $99 (Pro) |

Разрыв в 30–60 раз: OpenAI берёт $15 за миллион символов, ElevenLabs продаёт
пакетами. Второй провайдер стоил бы второго ключа, второго кода-пути и второго
источника отказов, поэтому его нет.

## Оформление

Две темы, обе снятые с иконки: светлая берёт её холодную половину (фон
`#EFF6FD`, синий акцент `#2E6BD6`), тёмная — индиго нижнего угла (`#0B1046`,
акцент `#5B4BE0`). Обе лежат в `src/theme.tsx`, переключаются солнцем и месяцем
в шапке, выбор сохраняется в AsyncStorage. По умолчанию светлая.

Тема реактивная: компоненты берут её через `useTheme()` и собирают стили
фабрикой `createStyles(theme)` — статический `StyleSheet.create` не переживает
переключения. Все пары текст/фон проверены на контраст, минимум WCAG AA
(на светлом фоне это жёстче: приглушённый текст и голубые подсказки пришлось
затемнить, иначе не проходили).

Значки солнца и месяца нарисованы фигурами, а не символами ☀ и ☾: шрифтовые
глифы выходят разными по весу, а iOS вдобавок подменяет солнце цветным эмодзи.

Главная кнопка не заливается акцентом, а строится на канте: светлый корпус с
сиреневым краем в светлой теме и тёмный с тем же кантом в тёмной. Токены
`ctaBg` / `ctaBorder` / `ctaText`. Кант проверен по порогу 3:1 для границ
элементов, текст — по 4.5:1: в светлой теме 3.83 и 6.21, в тёмной 5.34 и 7.87.

Иконка разложена по `assets/` (`icon.png`, `favicon.png`, adaptive-набор для
Android с фоном `#0B1046`). В Expo Go её не видно — там своя иконка; она
появится в собранном билде.

## Заставка

Портрет во весь экран под гонг, три секунды (`SPLASH_HOLD_MS`), поверх — имя
приложения, а снизу студия, автор и версия из `app.json`. Тап снимает заставку
сразу. Фон под снимком прибит к тёмному, а не взят из темы: в светлой теме перед
загрузкой картинки мелькала белая вспышка.

Нативная заставка (`expo-splash-screen`) настроена по платформам по-разному, и
это не прихоть. На iOS она показывает тот же снимок во весь экран, поэтому
переход к нашей незаметен. На Android начиная с двенадцатой версии заставку
рисует система, и она умеет только иконку в круге — изображение во весь экран
туда поставить нельзя. Поэтому там задан отдельный `android.image` с лицом
крупным планом: в круге оно читается, а портрет целиком человек видит следующим
экраном.

Гонг подрезан ровно под длительность показа, с затуханием в хвосте: иначе звук
обрывался бы на полуслове, когда картинка уже ушла. Резка — тем же приёмом на
AVFoundation, что в KukaViewer.

Держится по таймеру, а не по событию «звук доиграл»: на Android это событие
приходит мгновенно, пока файл ещё грузится, и заставка мигала. Звук —
`assets/splash.m4a` (4 с, скопирован из KukaViewer); чтобы поменять, положите на
его место свой файл. Границы показа в `src/config.ts`: `SPLASH_MIN_MS` (850 —
чтобы заставка не мигнула) и `SPLASH_MAX_MS` (6000 — потолок, если звук не
загрузился).

Нативная заставка Expo настроена в том же цвете `#0B1046`, а её скрытие
отложено до монтирования своей — иначе между ними мелькает белый кадр.

## Персонализация

В профиле задаётся имя и аватарка. Своё фото загружается из галереи или
снимается камерой (`expo-image-picker`), кадрируется квадратом при выборе.
Снимок копируется из временной папки в `Paths.document/avatar/` — иначе система
рано или поздно вычистит кэш и аватарка пропадёт.

Если своего фото нет, есть двенадцать готовых портретов — по четыре мужских,
женских и детских, в `assets/avatars/`, список в `src/avatars.ts`. Фото и
готовая аватарка взаимоисключающие: выбор одного сбрасывает другое, иначе
непонятно, что победит. Пока не выбрано ничего, рисуются инициалы имени.

Имя не украшение: оно уходит в system prompt, и партнёр иногда обращается по
нему — с оговоркой «не в каждой фразе», иначе выходит навязчиво.

У собеседника свои лица, по одному на роль (`assets/tutor*.png`):

| Файл | Когда показывается |
|---|---|
| `tutor.png` | по умолчанию — преподавательница |
| `tutor-clinic.png` | ролевая тема «у врача» |
| `tutor-bank.png` | «в банке» |
| `tutor-repair.png` | «ремонт бытовой техники» |

Карта лежит в `src/components/Avatar.tsx`: Metro требует статических путей в
`require`, собрать имя файла на лету нельзя. Добавить роль — положить картинку и
вписать строку. В архиве лицо берётся из темы той беседы, а не текущей.

## Домашнее задание

По итогам беседы приложение собирает упражнения из её же ошибок: строка
«Задание» в панели, кнопка «Составить задание». В модель уходит список
исправлений, обратно приходит структурированный разбор — две-три фразы о том,
над чем работать, и пять-десять упражнений трёх видов:

| Вид | Что делает |
|---|---|
| `fill` | вставить слово в пропуск |
| `fix` | найти ошибку в предложении |
| `translate` | перевести фразу на изучаемый язык |

Упражнения связаны с беседой в обе стороны. Модель возвращает номер ошибки, из
которой выросло упражнение; номер тут же разрешается в текст пары «сказал →
правильно» и хранится прямо в упражнении — задание уезжает в архив и должно
читаться само, без обращения к той беседе. В карточке эта пара показана строкой
«Из беседы», а в ленте исправления, попавшие в задание, помечены «в задании».

В промпте прямо запрещено брать предложения из беседы: те же правила, но новые
фразы, иначе запоминается ответ, а не правило. Ответ в карточке скрыт, пока его
не откроют, — иначе глаз цепляет его раньше, чем голова успевает подумать.

Задание живёт вместе с беседой: при уходе в архив переезжает под её
идентификатор и открывается из архива кнопкой «Задание», в списке беседа
помечается «с заданием». Это отдельный вызов модели с потолком 8192 токена —
роль другая, не собеседник, а преподаватель.

## Размер текста

В профиле три размера: обычный, крупный, очень крупный. Масштаб живёт в теме, и
стили каждого компонента прогоняются через `useStyles` — тот сам растягивает
`fontSize` и `lineHeight` в готовых правилах. Иначе множитель пришлось бы
вписывать в каждое правило вручную, и любое новое неизбежно про него забыло бы.

## Экспорт задания в PDF

Кнопка «PDF» в шапке задания собирает документ и отдаёт его в системное окно
«Поделиться». Порядок разделов: заголовок беседы, диалог целиком с разбором
ошибок, задания с местом для ответа, и ответы — **отдельной страницей в конце**
(`page-break-before`). Иначе взгляд цепляет ответ раньше, чем успеваешь подумать
над упражнением.

Разметка вынесена в `homeworkHtml.ts` без нативных импортов: её можно собрать и
проверить обычным Node, не поднимая симулятор. Весь текст, попадающий в HTML,
экранируется — туда идут реплики человека и ответ модели.

## Архив

Законченная беседа не стирается, а уходит в архив кнопкой «В архив» в шапке:
разбор ошибок и есть то, ради чего к беседе возвращаются. Метаданные списка
(язык, уровень, тема, даты, число реплик и ошибок, первая фраза) лежат одним
ключом, реплики — отдельным на беседу, и грузятся только при открытии. В архиве
беседа читается целиком, вместе с исправлениями и грамматикой под «?».

## Планшеты

Колонка контента ограничена `CONTENT_MAX_WIDTH` (640) и центрируется: на
тринадцати дюймах лента во всю ширину дала бы строки, которые неудобно читать.
Кнопки языка и уровня группируются по центру панели, а не расползаются по краям.
Поворот разрешён (`orientation: default` в `app.json`) — на планшете портретная
блокировка неуместна. Проверено на iPad Pro 11".

## Нативные проекты

`npx expo prebuild --platform all` собирает `ios/` и `android/` из `app.json` и
плагинов. Что при этом доезжает до нативной части:

| Что | iOS | Android |
|---|---|---|
| Доступ к микрофону | `NSMicrophoneUsageDescription` | `RECORD_AUDIO` |
| Поворот экрана | четыре ориентации, отдельно для iPad | `screenOrientation="unspecified"` |
| Фон приложения и заставки | `SplashScreenBackground` = `#EFF6FD` | `splashscreen_background`, `activityBackground` |
| Иконка | `AppIcon.appiconset` | `mipmap-*` + `iconBackground` `#0B1046` |

`expo-system-ui` обязателен: без него `backgroundColor` и `userInterfaceStyle`
из `app.json` молча игнорируются, о чём пребилд предупреждает в логе.

## Нижний край экрана

Кнопка беседы — плоская полоса во всю ширину внизу. Она лежит внутри
`SafeAreaView` с `edges={['top', 'bottom']}`, поэтому системный отступ снизу
приходит из инсетов, а не из константы: при трёхкнопочной навигации под кнопкой
остаётся 153 px, при жестовой — 90 px, и перекрытия нет в обоих режимах.
Проверено на эмуляторе Android с переключением обоих режимов.

## Что Whisper не доносит до разбора

Прогон на живых ключах показал: Whisper подменяет выдуманные формы слов на
ближайшие настоящие. Сказанное `I buyed` приезжает как `I buy`, и ошибка до
разбора не доходит.

Проверено, что проблема узкая. В одной фразе с ошибками разных типов —
`I go` вместо `went`, `I have not my passport`, `more cheaper`,
`How much documents I need` — уцелело всё. Не выживают только несуществующие
словоформы, которые звучат как реальное слово.

Подсказка Whisper с просьбой расшифровывать дословно результата не дала —
пробовал, не помогло, поэтому в коде её нет. Часть эффекта, вероятно, от самой
проверки: там речь синтезирована TTS, а живое произношение отчётливее.

## Заплатка на expo-modules-jsi

`ExpoModulesJSI` из Expo SDK 57 не собирается компилятором Swift 6.2 из
Xcode 26.2: три ошибки вида «sending 'argumentsPtr' risks causing data races» в
`JavaScriptRuntime.swift`. Подпись API объявлена через `sending`, поэтому
понижение языкового режима до Swift 5 не помогает — пробовал, ошибки остаются.

Заплатка в `patches/expo-modules-jsi+57.0.8.patch` везёт адреса указателей
целым числом (`UInt(bitPattern:)`), а на месте использования восстанавливает их
через `unsafeBitCast`. Целое отправлять между изоляциями можно, поэтому цепочка
проверок рвётся, а семантика не меняется. Накатывается автоматически:
`patch-package` прописан в `postinstall`.

Важно: **`unsafeBitCast`, а не `UnsafePointer(bitPattern:)!`**. При вызове
JS-функции без аргументов JSI передаёт нулевой указатель, optional-инициализатор
возвращает на нём `nil`, и принудительное развёртывание роняет процесс уже во
время работы, а не сборки.

Обновляться до `expo-modules-jsi@57.1.0` не нужно: там возвращается
`SWIFT_RETURNS_RETAINED` в `RuntimeScheduler.h`, который тот же Xcode тоже
отвергает. В установленном 57.0.8 этой аннотации нет.

## Отправка записи в Whisper

`fetch` у Expo принимает в `FormData` только строку, `Blob` или объект с
методом `bytes()`. Привычный для React Native `{ uri, name, type }` он отвергает
с «Unsupported FormDataPart implementation», поэтому запись кладётся объектом
`File` из `expo-file-system`. В Expo Go это не всплывало: там глобальный `fetch`
был реализацией React Native и uri-объект понимал.

`npx expo run:android` и `npx expo run:ios` собираются и ставятся — проверено.
Сборка iOS требует заплатки выше.
